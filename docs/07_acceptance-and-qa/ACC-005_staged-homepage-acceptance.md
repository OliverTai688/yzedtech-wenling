## 1. 結論

首頁已由「五章直向頁面」改為七張 slide 的故事舞台，文案與網址都沒有變。

| 項目 | 結果 |
| --- | --- |
| 首頁互動 | 24 項檢查全過，開發版與正式建置版各跑一次 |
| 四條轉化路徑 | 21 項檢查全過 |
| 版面：25 頁 × 4 種寬度 | 100 次檢查無橫向捲軸、無主控台錯誤 |
| 文案比對 docx | 全站 1,661 個字串，畫面文字與標題 0 個對不上；剩 3 個既有的隱藏無障礙標籤 |
| `pnpm lint`、`pnpm build`（29 個靜態頁）、`pnpm content:check`（9 條規則） | 通過 |
| 速度（模擬慢速 4G 手機） | 首頁首次繪製與最大內容繪製都是 1.41 秒，版面位移 0 |

驗證過程中找到並修掉的兩個問題，都只在正式建置版加上慢速網路時才會出現：

1. **畫面來回切換**。舞台有一道保險：程式遲遲沒接上時退回一般頁面。原本是固定等 5 秒，慢速網路下程式本來就晚到，結果畫面先退回一般頁面、幾秒後又換回舞台，最大內容繪製被拖到 6.2 秒。改成「頁面資源載完後再等 3.5 秒」，回到 1.41 秒。
2. **直接開啟帶錨點的網址停錯位置**（例如 `/#personas-section`、由 `/faq` 轉址來的 `/#home-faq`）。舞台啟用後版面高度會變，現在會重新捲到目標。

### 同一天稍晚的三項調整（使用者指示）

| 調整 | 內容 | 驗證 |
| --- | --- | --- |
| 書的內容印在書頁上 | 第 02 張不再有「＋」。捲動只略讀每個對象的第一頁；翻頁箭頭、頁角與鍵盤左右鍵可以往後翻到故事與專屬起點；書籤跳到某個對象。細節見 RES-005 §3 的修訂 | 實際操作截圖（手機與桌機）：箭頭依序翻到故事一、故事二、專屬起點，再接下一個對象，捲動位置同步移動 |
| 一個畫面一顆按鈕 | 全站每個手機畫面的內容最多一顆金色按鈕；第二個行動改成文字連結（`.btn-text`）；手機底部固定列是一顆金色主按鈕加一顆只有圖示的銀色圓鈕；每頁結尾的深色區塊以「私訊官方 LINE」為主按鈕 | 量測 11 個頁面的每個畫面：內容按鈕都是 0 或 1 顆 |
| 頁尾精簡 | 改成淺色、三欄等寬、沒有外框；內容一項未少 | 截圖；桌機高度約 610px |

調整後重跑的結果：首頁互動 24 項、四條路徑、100 項版面檢查、文案比對（1,660 個字串，剩 3 個隱藏標籤）全過；`pnpm lint`、`pnpm build`、`pnpm content:check` 通過；首頁首次繪製與最大內容繪製 1.38 秒，版面位移 0，下載的程式碼 267 KB。書這一張最密的一頁（手機）：文字佔畫面 17%、111 個字、一顆按鈕。

§2–§4 的敘述與數字是調整前量的；與上表不同的地方以上表為準。

## 2. 七張 slide 的現況

| # | 內容 | 釘住 | 畫面 |

| 01 | Hero | 是 | 暖白舞台，金翼羅盤橫跨畫面；先微微下壓再由內而外展開；主標換成「成為你豐盛之路上的翅膀」；之後一段沒有字的飛行 |

| 03 三階段 | 12–15% | 61% | 92–119 | 文字 ≤ 16%、主角 ≥ 40%、字 ≤ 120 |

## 4. 互動檢查的內容（24 項）

- 九個必要的錨點都在；只有一個 H1；載入時主標與主按鈕看得見、不是透明的。
- **捲動沒有被改寫**：手機指定捲到哪就停在哪；桌機滾輪 400 像素就是 400 像素。
- 書：書籤在畫面內；點「感情」後只有那一頁顯示、第一個連結是該對象的第一個按鈕；方向鍵可切換；選擇存進瀏覽器，重新載入仍記得。
- 手機底部固定列：預設「從這裡，開始我的改變」→ 選對象後換成該對象的按鈕 → 最後一章換成「加入免費體驗社群：密碼168168」。
- 三階段：圓點是按鈕；面板顯示該階段原文與原文點名的服務連結；Esc 可關。
- 常見問題四題、一次只開一題；三本書都連到媒體專訪。
- 頁首的商城按鈕與底部固定列沒有被任何東西蓋住。
- 手機詳細頁的 LINE 連結仍會帶入頁面名稱。
- **退路**：開啟「減少動態效果」或關閉 JavaScript 時，沒有釘住的舞台，所有標題都看得見；程式檔載入失敗時也會退回一般頁面。
- 桌機：舞台釘住時頁首導覽淡出、商城仍可用；離開舞台後恢復。

## 5. 已知的不足

| 項目 | 說明 |
| --- | --- |
| **沒有在實機上測過** | iOS Safari 的網址列伸縮、慣性捲動、3D 翻頁、每根羽毛各自轉動的效能，都只在模擬環境看過。這類釘住的捲動動畫最容易在實機出問題 |
| 研究指出的風險仍在 | 釘住的捲動在手機上容易讓人迷路（RES-004 §4）。這一版把釘住的段落限制在三張、每張約一個螢幕，但有沒有影響轉化要靠上線後的數據 |
| 手機 Hero 的翅膀尖端被裁切 | 為了讓主角夠大，金翼寬度超過螢幕 |
| 實作後半的子代理在最後回報前中斷 | 成品完整，由主代理逐項驗證；但它自己做過哪些測試沒有留下紀錄 |
| 舊的首頁元件還在 | `src/components/home/` 的 `NeedEntries`、`HomeStages`、`StagePath`、`GoldenPath`、`ChapterProgress` 已不再使用，驗收通過前保留，方便退回 |
| 檢查腳本沒有收進 repo | 互動、路徑、文案比對等腳本仍在開發時的暫存資料夾 |
| 金翼羅盤 | 替代圖形，依使用者提供的參考圖以向量重繪；亮片質感只能接近。設計系統裡的品牌素材尚未換成第二版 |
| 素材 | 創辦人照片與書封仍是佔位（RPT-001 G2、G3） |

## 6. 人工驗收清單

本機啟動：`pnpm install` 後 `pnpm dev`（3000 被佔用時用 `pnpm exec next dev --port 3100`）。

### A. 實機（最重要）

#### H-DEV-001 ｜ iPhone Safari 與 Android Chrome

| 步驟 | 操作 |
| --- | --- |
| 1 | 用手機開首頁，以平常的速度一路捲到底，再捲回頂端 |
| 2 | 快速甩動捲過整頁 |
| 3 | 在書那一張點四個書籤，各點一次「＋」再關掉 |
| 4 | 從 LINE、Instagram 的內建瀏覽器各開一次 |

- [ ] 捲動順暢，沒有卡頓、跳動或畫面閃白。
- [ ] 網址列伸縮時，舞台沒有上下跳。
- [ ] 快速捲動時不會卡在某一張出不來。
- [ ] 書的翻頁與面板的開關正常。
- [ ] 底部固定列沒有被系統列遮住，也沒有蓋住內容。

### B. 故事與畫面

#### H-STORY-001 ｜ 劇場感

- [ ] 每張 slide 一眼看得出主角是什麼，文字不再是畫面的主體。
- [ ] 金、銀、暖白的比例合意；銀色只是少量。
- [ ] 金翼羅盤從 Hero 到創辦人那一張，看起來是同一個主角在移動。
- [ ] 01–03 釘住的長度不會太長，想往下找資訊的人不會不耐煩。
- [ ] 04–07 有「喘口氣」的感覺，和前面的節奏有區別。

#### H-STORY-002 ｜ 各張的細節

- [ ] 01：金翼的大小與翅膀尖端被裁切的程度可以接受。
- [ ] 02：書的樣子可以接受；用箭頭或頁角往後翻，看得到故事與專屬起點；翻頁的提示（箭頭輕閃、翹起的頁角）夠明顯但不干擾。
- [ ] 02：手機上書頁裡的金色按鈕與底部固定列的金色按鈕是同一個行動，同時出現是否可以接受。
- [ ] 03：放射圖是你要的意象；階段與服務的名稱清楚。
- [ ] 05：三本文字封面的書在沒有書封照片前可以接受。
- [ ] 06：密碼數字的呈現可以接受。

### C. 內容與行動

- [ ] 每個畫面只有一顆按鈕的做法可以接受；文字連結看得出可以點。
- [ ] 每頁結尾的主按鈕是「私訊官方 LINE」，同意（或指定改成別的）。
- [ ] 「關於我們」最後一區的社群連結、培訓課程每門課的「報名」現在是文字連結，是否要改回按鈕。
- [ ] 精簡後的頁尾可以接受。
- [ ] 「＋」裡的補充內容找得到、讀得完。
- [ ] 每一張都知道下一步可以點哪裡。
- [ ] 選過對象後，底部的按鈕換成對應的服務，符合預期。

### D. 退路

- [ ] 在手機的輔助使用設定開啟「減少動態效果」後重新整理：首頁是一般的直向頁面，內容完整。
