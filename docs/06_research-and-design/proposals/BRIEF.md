# 分頁提案共用規範（PLN-004 階段 D）

每個分頁先做三個 HTML 提案（A／B／C），再由 AI 評分、整合成一個方向後實作。本檔是所有提案共用的規範；各頁的區塊需求見 RES-001 §6，缺口見 RPT-001。

## 1. 品牌與調性

- 品牌：**豐盛之翼學苑**（不可寫成「學院」）。文齡老師的身分是「創辦人」。
- 感受：金色光感、財氣豐盛、溫暖而專業。**不用粉色**。簡約，留白多於裝飾。
- 圖形母題：金色雙翼與羅盤（學苑 Logo）、暖光散景、向上流動的金色光塵。

## 2. 設計 token（直接貼進提案的 `:root`）

```css
:root {
  --background: #FBF1DD;  --foreground: #2E2318;
  --card: #FDF6E6;        --card-foreground: #3A2A18;
  --popover: #FFFDF0;
  --primary: #C9862E;     --primary-foreground: #3A2409;
  --secondary: #FFFDF0;   --secondary-foreground: #8A5415;
  --muted: #FDF6E6;       --muted-foreground: #7A6650;
  --accent: #FCE7A8;      --accent-foreground: #8A5415;
  --border: #F0DFA0;      --ring: #B5762A;
  --inverse: #20140A;     --inverse-foreground: #F5E4C8;  --inverse-accent: #F0C875;
  --gold-100: #FCE7A8; --gold-300: #E8B15A; --gold-500: #C9862E; --gold-600: #B5762A; --gold-700: #8A5415;
  --line: #06C755;        --line-foreground: #0B2E18;
  --font-serif: "Noto Serif TC", serif;  --font-sans: "Noto Sans TC", sans-serif;
}
```

- 一般大小的金色文字用 `--accent-foreground`；`--gold-600` 只用在圖示、邊框、18px 以上標題。
- 主按鈕：金色漸層（`--gold-100` → `#D89A3E`）配 `--primary-foreground`，全圓角。LINE 按鈕：`--line` 底配 `--line-foreground`。
- 字級：H1 32/40、H2 26/32、H3 20、內文 16、註記 14（手機／桌機）。標題用襯線體。
- 卡片圓角 18px；區塊上下間距手機 64px、桌機 96px；點擊目標至少 44px 高。

## 3. 動效方向

- 預設強度「光感」：功能性（M1）與敘事性（M2）動效必做，品牌光感（M3）是重點。
- 要有**捲動推進的互動**：捲動本身推動一段敘事（例如光的路徑延伸、雙翼展開、鏡頭前進），不是只有淡入。
- 可以用 three.js 或 Canvas 做 3D／粒子，但要克制：2026 年的趨勢是以捲動敘事為主，單純鋪一層粒子背景已經氾濫。3D 只放在能強化品牌記憶的位置。
- 3D 的主角是金翼與羅盤（Logo）；只出現在首頁 Hero 與最終 CTA，內頁不放 3D（RES-003 §5）。
- 不鎖住捲動、不強迫看完動畫才能讀內容。
- 參數：快 150ms、標準 250ms、慢 500ms；進場上移 16px 加淡入；依序延遲 70ms、一組最多 6 個；每個元素只播一次。
- 底線：
  - 主標題不可因動畫延後顯示（不從透明開始）。
  - 只動 `transform` 與 `opacity`，不造成版面跳動。
  - 手機（寬度小於 768px）不做視差，3D 要降階或關閉。
  - 同一畫面持續循環的動效最多 2 個。
  - `prefers-reduced-motion: reduce` 時關閉位移、視差、循環與 3D。
  - WebGL 不可用時要有靜態替代畫面。

## 4. 內容規則

- 文案只用 `src/data.ts` 與 `docs/網站文案集.md` 已有的文字，逐字使用，不改寫、不自行新增見證、數字或承諾。
- 需要但還沒有的素材，用明確標示的佔位框，例如「創辦人形象照（待提供）」。佔位不放假照片、假姓名。
- 見證尚未取得授權：提案可以放文案集的匿名引言來呈現版型，但要在區塊角落標「待授權」。
- 連結用 `src/data.ts` 的 `siteLinks`。站內連結寫實際路由（`/services/group-healing` 等）。

## 4A. 文字密度與漸進揭露（2026-10-05 新增）

文案很長，而且不能改寫。設計要解決的是「不要讓很多字同時出現在同一個畫面」，做法是控制先看到什麼、其餘由訪客自己展開。

- **一個畫面一個重點**：每個視窗高度內，預設可見的內文（不含標題與按鈕）桌機不超過約 150 字、手機不超過約 100 字。
- **卡片預設狀態**：標題加一句話。完整內容（故事、條列、說明）預設收起，由分頁、展開、切換來揭露。
- **多個同類項目不並排攤開**：四類需求、三本書、多則見證、多門課程，一次只展開一個；其餘只露出標題。
- **用版面轉場銜接**：展開、切換時，元素平滑移動或交叉淡入，讓訪客看得出內容從哪裡來（實作用 `motion` 的 layout 動畫）。
- **不藏主行動**：CTA 永遠在預設狀態就看得到，不需要先展開。
- **不截斷文案**：不可用「…」截掉句子。要嘛整句顯示，要嘛整段收起。
- 收起的內容仍要在 HTML 裡（對搜尋引擎與無 JavaScript 的訪客可讀）。

## 5. 轉化規則（RES-001 §4.2）

- 每個視窗內最多一顆主按鈕，其餘用次要樣式。
- 每頁結尾有 CTA 區塊：「了解適合我的服務」與「加入官方 LINE 諮詢」。
- 首頁主內容的對外連結不超過 10 個。
- 詳細頁在手機要有底部固定列（預約或報名＋LINE）。
- 首頁在手機也要有底部固定列，捲過 Hero 後出現（RES-003 §3.2）。

## 6. 提案檔案格式

- 一頁一個獨立的 `.html`，CSS 與 JS 都內嵌，直接用瀏覽器開啟即可看。
- 可從 CDN 載入：Google Fonts（Noto Serif TC／Noto Sans TC）、`three`（jsDelivr 的 ES module 或 cdnjs）。不用其他函式庫。
- 以手機 375px 為主設計，桌機 1024px 以上要完整可用；任何寬度都不可水平捲動。
- 導覽列照方案 C：Logo｜關於我們▾｜療癒與培訓▾｜客戶見證｜媒體專訪｜更多▾｜LINE 諮詢｜商城。手機是 Logo＋商城＋選單鈕。提案裡導覽不必可操作。
- 檔案開頭放一段 HTML 註解：提案代號、概念一句話、用到的動效技術、已知弱點。
- 頁面左下角放一個小標籤「提案 A／B／C・概念名稱」。

## 6A. 第 2 頁起的提案（首頁定案之後）

首頁已定下整站的視覺語言（RES-002 §1）。其餘各頁的三個提案**不再比較視覺風格**，而是在同一套語言之內，比較「資訊怎麼分層、訪客怎麼走到 CTA」。

- 一律使用 [`_kit.css`](./_kit.css)（`<link rel="stylesheet" href="../_kit.css">`）與 [`_shell.html`](./_shell.html) 的外殼，只寫該頁的 `<main>` 與專屬樣式。不要重寫 token、按鈕、卡片、頁首頁尾。
- 內頁不放 3D、不放粒子。動效只用：一次性的進場（`.reveal`）、展開收合（`.disclosure`）、分頁切換、版面轉場。
- 三個提案的差異要落在：內容的分層方式（分頁／展開／步驟／比較）、第一個畫面放什麼、CTA 放在哪裡與出現時機。
- 文案很長的頁面（服務與課程詳細頁），重點是 §4A：第一個畫面只回答「這是什麼、適不適合我、下一步是什麼」，其餘內容分層收起。
- 不需要自行用瀏覽器測試。寫完後自己讀一遍檢查即可；截圖與量測由主流程統一執行。
- 檔案控制在約 600 行以內。

## 7. 評分標準（AI 整合挑選時使用）

依 RES-003 的轉化數據調整：數據最支持的是速度與 CTA 的可及性，動效的價值在於把視線帶向下一步。

| 項目 | 配分 |
| --- | --- |
| 轉化路徑清晰（主行動明確、步數少、手機第一屏或固定列看得到） | 25 |
| 文字密度與漸進揭露（同一畫面不堆字，§4A） | 20 |
| 動效是否把視線帶向 CTA，而不是擋住閱讀 | 15 |
| 品牌光感與財氣豐盛的感受 | 15 |
| 手機體驗（長度、點擊目標） | 15 |
| 效能、無障礙與實作風險 | 10 |

整合時不一定整份採用單一提案，可以取各案最好的區塊，但整站的視覺語言以首頁定案的方向為準。
