# 其他分頁（第二輪）：共用簡報

**日期：** 2026-10-06　**計畫：** [`PLN-006`](../../../04_execution-plans/PLN-006_inner-pages-proposal-and-optimisation.md)
**必讀：** [`ARC-002`](../../../02_architecture-and-rules/ARC-002_ui-and-interaction-rules.md)（文案、按鈕、色彩、素材的規則）

每個分頁先做一份 HTML 提案，再實作。這份簡報是所有分頁共同的要求。

## 1. 使用者要的是什麼

- 乾淨、專業。和首頁是同一個品牌：金、銀、暖白，金翼羅盤。
- **不用捲動動畫**：沒有釘住的舞台、沒有隨捲動推進的時間軸。可以有的動態只有：進入畫面時一次性的淡入、展開收合、分頁切換、面板滑出、滑鼠移過的回饋。
- **文字不能一次讀太密**：用介面操作把內容分層（分頁、收合、一次看一則、點了才滑出的面板、頁內的小導覽）。
- **旅程要順**：每一頁知道訪客從哪裡來、這一頁要他做什麼、看完去哪裡。

## 2. 硬性規則

1. **文案只能逐字取自 docx**（`src/data.ts`、`src/content/**` 裡現有的字串）。不新增、不改寫、不摘要。沒有對應文字就用數字、圖示或版面表達。提案與實作都一樣。
2. **路由、網址、錨點、連結目的地不變。**
3. **一個畫面一顆按鈕**（`.gold-btn`）。第二個行動只有在門檻更低或文案集本來就有時才保留，一律做成 `.btn-text`。清單每列各自的行動也是 `.btn-text`。
4. **顏色只用 token**（`app/globals.css` 的 `@theme`），不寫色碼。不用綠、粉、紫、藍。銀色只是少量。
5. **手機優先**。先排 390px。可點的東西高度至少 44px。沒有橫向捲軸。
6. 每頁恰好一個 H1；標題層級不跳級；圖形加 `aria-hidden`；鍵盤可以操作所有互動；焦點看得見。
7. 沒有 JavaScript 時內容仍然讀得到（收合用原生 `<details>`；分頁在沒有 JS 時全部攤開）。
8. 不放照片與書封（素材未到）；佔位用拱形或文字封面，並保留 `data-placeholder`。不放未授權的見證。
9. 每頁結尾是共用的 `CtaBand`，之前是「下一站」（§5）。

## 3. 預算（手機 390×844，每一個畫面）

| 項目 | 上限 |
| --- | --- |
| 看得到的內文（不含標題、按鈕、收合中的內容） | 目標 100 字，上限 140 字 |
| 按鈕樣式的行動 | 1 顆 |
| 可點的東西（不含頁首與底部固定列） | 8 個 |
| 頁面長度 | 不超過目前的長度（各頁在自己的 `PAGE.md` 註明現況） |

超過字數上限的地方，要用操作分層，不能縮小字或截斷。

## 4. 每一頁的第一個畫面

第一個畫面要回答三件事：這一頁是什麼、對我有什麼用、我可以做什麼。組成固定為：

- 一個 H1（文案集的頁名或標題）、最多一句導言、一顆按鈕或一個清楚的操作起點（例如分頁列）。
- 一個安靜的視覺焦點：金翼小標誌、該頁的圖示或拱形佔位，放在暖白的底上，帶一圈很淡的金色光暈。不做大面積的漸層橫幅。
- 用共用的 `PageHero`，不要各頁自己刻。

## 6. 可以用的操作（都不需要新文字）

| 操作 | 用在哪 | 元件 |
| --- | --- | --- |
| 分頁（一次看一組） | 對等的幾組內容 | `ChipTabs` |
| 收合（一次開一個） | 問答、條款、長段落 | 原生 `<details name>`、`.disclosure` |
| 一次一則，左右翻 | 故事、見證、媒體單集 | 翻頁箭頭（圖示）加小圓點 |
| 面板 | 點清單的一列，看細節而不離開頁面 | `PageSheet` |
| 頁內小導覽 | 長頁的幾個區塊 | 一列錨點連結，文字用各區塊既有的標題 |
| 篩選 | 清單 | 既有的類型篩選 |

箭頭、圓點、關閉鈕只用圖示；`aria-label` 用既有字串（要去的那一項的標題）。

## 7. 審查標準（主代理據此審提案與實作）

| 項目 | 配分 | 看什麼 |
| --- | --- | --- |
| 旅程與行動 | 25 | 第一個畫面講清楚這頁是什麼；唯一的按鈕對；下一站對 |
| 文字分層 | 25 | 每個畫面在字數預算內；分層的操作直覺；沒有內容被藏到找不到 |
| 一致與專業 | 20 | 和首頁、設計系統同一個語言；間距、對齊、圓角、按鈕一致 |
| 手機體驗 | 15 | 390px 完整可用；點擊目標；單手可操作 |
| 無障礙與退路 | 10 | 鍵盤、標題層級、沒有 JS 也讀得到 |
| 風險 | 5 | 效能、維護成本 |

低於 80 分的提案要修到 80 分以上才實作。

## 8. 每批的交付

1. `docs/06_research-and-design/proposals/pages-v2/<page>/PAGE.md`：現況的問題（附量測）、這一頁的旅程角色、分層的做法、與上一版的差異、未解的問題。
2. `…/<page>/index.html`：可直接開啟的提案（用 `_kit.css` 與 `_shell.html`），390px 與 1280px 都要正常。
3. 實作：只改自己那一批的頁面元件，使用共用元件；不修改共用元件與其他批的檔案。
4. 檢查：截圖（讀圖判斷）、字數與按鈕數量測、文案比對、型別與 lint。
5. 回報：每頁的自評分數、量測數字、沒做到的地方。
