# `/services` 服務項目（P2）

**提案：** [`index.html`](./index.html)（加 `?need=family`、`?need=love`、`?need=business` 可看「記得的對象」的狀態）
**共用要求：** [`../BRIEF.md`](../BRIEF.md)

## 1. 現況（手機 390×844，2026-10-06 量測）

| 項目 | 數字 |
| --- | --- |
| 頁面長度 | 4,069px（4.8 個畫面） |
| 單一畫面內文 | 量測工具回報最多 60 字；但八張卡整張都是連結，卡片裡的一句話沒被算進去。實際每個畫面有 3～4 張卡，約 110～150 字 |
| 按鈕 | 第一個畫面 1 顆金色按鈕＋1 個 LINE 文字連結；結尾區塊 1 顆 |

問題：

1. 第一個畫面的金色按鈕把人帶回首頁選對象，訪客還沒看到清單就被請走；這一頁真正的行動是「進入某一項服務」。
2. 每張卡都重複一個類型標籤，和上方的篩選列講同一件事，畫面比較吵。
3. 自己刻的頁首，和其他內頁不是同一個第一個畫面；結尾沒有下一站。
4. 訪客在首頁選過對象，這一頁沒有反映。

## 2. 旅程角色

訪客想找適合自己的服務。這一頁要他做的事只有一件：挑一項，進詳細頁。上一站是品牌理念，下一站是培訓課程。

## 3. 做法

- **第一個畫面**（`PageHero`）：金翼小標誌、H1「服務項目」、一句導言（Home Block 3 副標）、類型篩選五個 chip。沒有金色按鈕；手機底部固定列與結尾區塊照舊。
- **清單**：一張卡＝名稱（H2）＋一句話＋一個文字連結「了解詳細服務說明」；連結的可點範圍蓋滿整張卡，所以一張卡只有一個連結。類型標籤拿掉。
- **篩選**：沿用現有做法（八張卡都在 HTML，沒選到的加 `hidden`，View Transitions 漸進增強）。沒有 JavaScript 時篩選列不顯示，八張卡全部列出。
- **記得的對象**：訪客選過的對象的第一個 CTA 若指向某項服務（家庭→人生推進器、感情→心靈引渡人、事業→豐盛靈氣），那一張排到最前面，卡片上方以眉批樣式標上對象既有的短名（「家庭」「感情」「事業」），外框換成金色。「新手」的第一個 CTA 是課程，這一頁不標。
- **下一站**：`JourneyNext route="/services"`，之後是 `CtaBand`。

## 6. 未解的問題

- 清單中段的畫面約 124～132 字，在上限 140 之內但高於目標 100。八句一句話是這一頁的本體，再降就得把一句話收起來，反而找不到。
- 八個連結的文字都是「了解詳細服務說明」，以 `aria-describedby` 指向各自的服務名稱來區分。
- 選過對象的訪客，卡片是在程式接上之後才重排，會有一次位移（選擇只存在瀏覽器，伺服器不知道）。
- 服務類型的歸類仍待客戶確認（RPT-001 C5）。
