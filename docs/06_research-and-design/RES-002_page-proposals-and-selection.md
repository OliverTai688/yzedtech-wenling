每個分頁先產出三個獨立的 HTML 提案，再依 BRIEF §7 的六項標準評分，選定或整合後實作。本文件記錄每一頁的三個概念、評分、定案與整合說明。

評分項目與配分：轉化路徑 25、文字密度與漸進揭露 20、動效指向 CTA 15、品牌光感 15、手機體驗 15、效能無障礙與風險 10。

「文字密度與漸進揭露」是 2026-10-05 看過首頁提案 A 後新增的：文案長且不能改寫，設計必須控制同一畫面出現的字數（BRIEF §4A）。

## 1. 首頁 `/`

**提案檔**：[`proposals/home/a.html`](./proposals/home/a.html)、[`b.html`](./proposals/home/b.html)、[`c.html`](./proposals/home/c.html)

| | A 金光之路 | B 光塵之境 | C 展翼羅盤 |
| --- | --- | --- | --- |
| 概念 | 一條金色光線隨捲動往下畫，串起每個區塊，最後通到 CTA | three.js 的景深金色光塵；深色 Hero，捲動時鏡頭朝光源前進 | 捲動時金翼展開、羅盤指針依序指向四類需求，一次顯示一張需求卡 |
| 技術 | SVG 加原生 JS，純 2D | three.js 粒子與著色器 | CSS 3D 變形、Canvas 2D 光點；桌機用固定舞台 |

### 評分

| 項目（配分） | A | B | C |
| --- | --- | --- | --- |
| 轉化路徑清晰（25） | 20 | 18 | 19 |
| 文字密度與漸進揭露（20） | 8 | 7 | 16 |
| 動效指向 CTA（15） | 12 | 5 | 11 |
| 品牌光感與財氣（15） | 9 | 13 | 13 |
| 手機體驗（15） | 12 | 11 | 12 |

| **合計** | **69** | **59** | **76** |

### 評語

- **A**：版面最乾淨，金線一路通到最終 CTA 的想法最能「指路」。主要問題是桌機把四張需求卡的全文同時攤開，一個畫面超過 600 字；使用者看過後也指出這點。蛇形路徑要靠 JS 量測版面，實作脆弱。
- **B**：深金色 Hero 的財氣感最強，但偏離奶油底的品牌 token；3D 只出現在頭尾，中間八個螢幕是一般卡片，粒子本身不指向任何行動。需求卡同樣四張全文並排。為一個粒子場景多載入約 190KB，不符 RES-003 的結論。
- **C**：唯一解決文字密度的一案——需求入口一次只出現一張卡，指針指向目前的類別。金翼與羅盤就是學苑的 Logo，品牌記憶最強。問題是桌機的固定舞台要捲三個螢幕才看完四類，接近鎖定捲動；每格重繪羽毛有掉幀風險；卡片內文仍一次全部顯示。

### 定案：以 C 為骨幹整合

| 區塊 | 採用 | 調整 |
| --- | --- | --- |
| Hero | A 的奶油底編排 | 主標題不做透明進場；其餘元素依序進場 |
| 需求入口 | C 的金翼羅盤加「一次一類」 | **不固定舞台、不鎖捲動**：改為四個方向按鈕切換，指針轉向所選類別；雙翼隨區塊捲入視窗而展開（捲動推進但不擋路）。卡片預設只顯示痛點、專屬起點與 CTA，兩則故事收成可展開的標題，一次開一則 |
| 全頁脊線 | A 的金線 | 簡化成版面左側的直線，進度用 `transform` 推進，節點在各區塊標題旁亮起；不用 JS 量測蛇形路徑 |
| 精選服務、媒體、FAQ | A 的緊湊編排 | 書籍只露出書名與角色，說明留在 `/media`；FAQ 用 Accordion |
| 最終 CTA | B 的深金光感 | 用 CSS 光暈，不用 three.js |
| 手機 | C 的靜態徽章加分頁 | 捲過 Hero 後出現底部固定 CTA 列（RES-003） |

- **3D**：首發不載入 three.js。金翼先用 SVG；Logo 向量檔到位、且上線數據支持時，再把 Hero 升級為 3D（RES-003 §5）。
- **金翼圖形是替代品**：取自 C 案自繪的 SVG，客戶的 Logo 到位後替換（RPT-001 G1）。
- **不上線的區塊**：新手入門引導（等文案 T1）與精選見證（等授權 C1）。資料與元件先做好，以開關控制。
- **創辦人簡介**：短簡介（T2）未到，先用文案集 About 的使命宣言原文。
