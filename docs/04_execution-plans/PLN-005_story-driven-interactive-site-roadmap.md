## 1. 開發目標

把階段 D 完成的品牌網站，推進成**有明確主題、CTA 有深度、靠小元件漸進推進**的故事型互動網站。

範圍：

- 一個貫穿全站的主題（建議「改變地圖」，RES-004 §3）。
- 六階的承諾階梯，補上目前最空的中段（RES-004 §5）。
- 一組只需要捲動或點一下的小元件（RES-004 §9）。
- 一批新的視覺素材與對應的客戶需求清單（RES-004 §8）。
- 先量測、再改版、再比較。

不在範圍：會員、金流、後台、AI 聊天。這些若要做需另開 PRD。

原則（延續前幾階段）：

1. 文案只用文案集原文；新增的任何一句話都由客戶提供或確認。
2. 版面有實質改變的頁面仍走「三個 HTML 提案 → AI 定案 → 實作」。
3. 頁面永遠以原生方式捲動；手機不做固定舞台（RES-004 §4.2）。
4. 任何時候都能直接預約，故事不擋路。
5. 每一階段結束時 `pnpm lint`、`pnpm build`、`pnpm content:check` 通過，並重量速度。

## 4. 各階段細節

### F0 定調與基礎

**缺口**：主題還沒被正式選定；新元件沒有規範；階段 D 還沒合併。

**步驟**

1. 推送 `feat/second-revision-phase-d` 並開 PR（決定 5）。
2. 寫 `PRD-004`：主題、承諾階梯、元件範圍、素材與文案需求、量測定義。
3. 寫 `ARC-002` UI 規範：色彩與字級 token、間距、收合與分頁的用法、動效參數、文字密度規則、「每個元件只能要求捲動或點一下」。
4. 建 `/ui-kit` 展示頁（不列入導覽與網站地圖），把現有元件與之後的新元件都放進去。
5. 移除未使用的相依與型別（決定 3）。
6. 首頁敘事的三個 HTML 提案：同一個主題、三種章節呈現方式（例如路徑線貫穿、章節卡片堆疊、桌機側邊進度），評分後定案，記入 `RES-002`。
7. 把 RES-004 §8 的素材與文案需求併入 `RPT-001`，產出給客戶的需求單（含拍攝清單）。

**完成條件**：PRD-004 核可；首頁敘事定案；需求單已交給客戶。

### F1 量測基準

**缺口**：沒有任何行為數據（RES-004 §6）。Vercel 免費方案不支援自訂事件。

**步驟**

1. 確認客戶的 Vercel 方案，定下工具（決定 7）。
2. 客戶確認隱私權政策的更新文字（T12）。在此之前不上線任何追蹤。
3. 實作 `src/lib/track.ts`：單一函式，背後可換工具；沒有工具時不做任何事。
4. 在現有的行動點加事件：需求分頁、固定列、每頁結尾行動區塊、LINE、預約、免費社群。
5. 站外連結加來源參數，並實測預約系統是否保留。
6. 部署後收集兩週，記錄基準：各頁到達率、各行動的點擊率、裝置與來源分布、內建瀏覽器比例。
7. 實機測試 LINE、Instagram、Facebook 的內建瀏覽器（RES-004 §10 第 2 項）。

**完成條件**：基準數據寫入一份 `RPT-002`；RES-004 §10 的第 1、2 項有答案。

**風險**：流量太低時兩週不足以比較。若每週預約點擊少於約 30 次，F6 只能做方向性判斷，並以操作錄影補足。

### F2 敘事骨架

**缺口**：首頁各區塊是並列的，沒有「章」的感受；三階段只出現在 `/about`。

**步驟**

1. 新增章節資料：`src/data.ts` 的 `homeContent` 加上五章的定義（編號、標題來源、色溫）。標題先沿用原文的區塊標題，T10 到位後替換。
2. 元件：章節容器、章節進度、章末下一步卡。路徑線與金翼展開沿用現有的 `GoldenPath`、`WingsCompass` 並擴充。
3. 把三階段（淨化與釋放／滋養與修復／顯化與推進）以節點形式帶進首頁，內容取自 `pageContent.about`，每個節點只連結原文在該階段點名、且本站有對應頁面的項目（例如煙供、香水供、人生推進器、金錢靈氣、人魚靈氣、希塔療癒），不自行歸類。
4. 色溫漸變與數字進場。
5. 桌機的固定舞台只用在「路怎麼走」一章，長度不超過兩個螢幕；手機改為直向排列。
6. 量測：首頁長度、每個畫面的字數、速度；與 ACC-003 的數字比較。

**完成條件**：首頁手機長度不超過 11 個螢幕（現為 9.3）；單一畫面內文不超過 160 字；首次繪製不慢於 1.5 秒；四條路徑測試仍全數通過。

### F3 深入 CTA

**缺口**：承諾階梯的第 2、3、4 階（RES-004 §5.1）。

**步驟**（依不需要客戶輸入的程度排序）

1. **LINE 帶話**：`siteLinks` 增加產生帶話連結的函式。手機用 `line.me/R/oaMessage`，桌機維持 `lin.ee`。帶入的文字先只用服務或課程的正式名稱（原文），T11 確認後再加上問候句。實機測試未加好友者的行為。
2. **會變的固定行動列**：擴充 `StickyCtaBar`，依目前章節與所選方向換文字與連結。
3. **行動抽屜**：手機點固定列時由底部滑出三個選項（預約、LINE、免費社群）。走三提案（與現有固定列比較）。
4. **直播倒數卡**：依「每週一晚間 21:30–22:30」計算下一場，提供加入行事曆。C12 確認前只顯示固定時間，不顯示倒數。
5. **記住選擇**：把需求入口的選擇存在瀏覽器，`/services` 與固定列據此調整。
6. **預約三步**：T14 到位後加在詳細頁的預約按鈕旁。
7. **30 秒找起點**：開發端依原文整理題目草稿與對應表，交客戶確認（T13、C11）。走三提案。結果頁直接顯示，不收 Email。以功能開關上線，方便在 F6 比較。

**完成條件**：每一階都有對應事件；LINE 帶話在 iOS 與 Android 實機驗證；四條路徑測試擴充為涵蓋新的階梯。

**風險**：引導的題目與結果用語容易碰到法規邊界（RES-004 §7）。結果只說「可以從這裡開始了解」。

### F4 視覺素材第一批

**缺口**：全站目前沒有任何照片或插畫，視覺只有漸層、圖示與替代的金翼圖形。

**步驟**

1. 客戶回覆 C13 與提供 G1–G3。
2. 做一張定調圖（G12），確認方向後，以它為風格參照產出方向圖像（G13）與階段圖像（G14）。每張都要人工檢查並修整。
3. 圖示組（G15）：決定委託繪製或以現有線條圖示加金色處理。
4. 小動畫（G18）：羽毛、指針、光點，以 SVG 加 CSS 製作。
5. 各頁分享圖（G21）。
6. 建立 `public/images/` 的命名與尺寸規範，寫入 ARC-002；全部經 `next/image`。
7. 換上正式 Logo，移除替代圖形。
8. 重量速度。

**完成條件**：首頁每一章至少有一個非文字的視覺焦點；手機首次繪製仍在 2.5 秒內；替代圖形與佔位全部換掉（未到的素材明列）。

**風險**：AI 圖像風格飄移、看起來像圖庫。對策是一次產完一批、固定色碼、不合格就不用，寧可留白。

### F5 各頁的故事化

**缺口**：主題目前只會出現在首頁。

**步驟**（每一項都走三提案）

1. `/story`：五章配上照片（G16），成為「創辦人走過的地圖」；G20 到位後加影片。
2. 服務與課程詳細頁：加入過程時間軸（G17），結尾加上「之後可以去哪一站」。
3. `/services`、`/training`：改成路線總覽，套用記住的選擇。
4. `/testimonials`：C1 授權後開啟，做成「別人走過的路」。
5. `/media`：補足三提案（決定 1），加入節目封面（G8）。
6. 跨頁轉場：從卡片進詳細頁時標題與圖示延續，先在 `/services` 試。
7. `/start` 新手入門：T1 到位後建立，並接回 P2 路徑。

**完成條件**：每個頁面都說得出自己在地圖上的角色；路徑測試、連結檢查、100 項版面檢查全數通過。

### F6 比較與取捨

**步驟**

1. 與 F1 的基準比較：各階的到達率與點擊率。
2. 有功能開關的項目（引導、行動抽屜、固定列文字）做對照。
3. 看操作錄影：人停在哪一章、哪個元件沒有人點。
4. 沒有幫助或拖慢速度的元件移除，寫明理由。
5. 寫 `ACC-004` 驗收報告。

**完成條件**：每個新元件都有「保留、調整或移除」的結論與數據依據。

## 6. 風險

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 故事做得太重，擋住想直接預約的人 | 轉化下降 | 原生捲動、固定行動列常駐、每章都有出口；F6 以數據檢查 |
| 素材遲遲不到 | F4、F5 停擺 | F0–F3 不依賴素材；F4 中可自製的部分先做 |
| 新文案來不及 | 章節沒有標題、引導無法上線 | 標題沿用原文；引導以功能開關延後 |
| 元件變多，速度變慢 | 首次繪製回到 3 秒以上 | 每階段重量；互動元件延後載入；不引入動畫播放器 |
| 流量不足以比較 | 無法判斷有效與否 | 加上操作錄影與客戶訪談（RES-004 §10 第 3 項） |
| 用語踩到法規 | 罰鍰與品牌風險 | 新文字一律由客戶確認，建議經法律顧問看過 |
